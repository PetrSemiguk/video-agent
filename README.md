# video-agent

Pipeline for producing English-language geo-history YouTube videos (12–14 min)
built on animated satellite maps with 3D terrain.

Topic → script → TTS voice → word timings → storyboard → Remotion render → final mix → thumbnail.
See [docs/pipeline.md](docs/pipeline.md) for the eight stages.

- `studio/` — Remotion project (video composition)
- `pipeline/` — Python tooling via uv (TTS, whisper, geo scripts)
- `episodes/<slug>/` — per-episode script, facts, storyboard, audio, renders
- [docs/style-guide.md](docs/style-guide.md) — visual style
- [docs/licenses.md](docs/licenses.md) — allowed and forbidden data sources

**Status:** Roadmap step 4.5: sequential, cached episode builds and a rendered
67.6-second pilot. Scripts and storyboards remain authored, reviewed inputs.

## Make an episode

Use native Windows PowerShell with the existing Node/npm, uv Python 3.11
environment and system ffmpeg setup. See [python-env.md](docs/python-env.md).
Run the following commands **from `pipeline/`**; never activate the venv manually.

Prepare `episodes/<slug>/` with:

- `script.md`: reviewed English narration; Markdown headings/comments are unspoken.
  Review and approve the text before running voice synthesis.
- `facts.md` and `attributions.md`: claim/source ledger and licensed media credits.
  Register new sources in [licenses.md](docs/licenses.md) before use.
- `storyboard.json`: authored using [components.md](docs/components.md) and the
  [storyboard contract](docs/storyboard.md). Its `episode.slug` must match the
  directory. Phrase/word anchors are resolved after alignment. Storyboard is
  required starting at the preview stage; it is not generated by this command.
- Optional `voice.job.json`: existing voice settings (`exaggeration`, `cfg`, `seed`,
  `max_chars`, `seed_overrides`, `voice`). Defaults are 0.3 / 0.5 / 42 / 240 / built-in
  voice. A reference path is resolved relative to `pipeline/`; use only an owned or
  licensed voice. The builder always selects this episode's script/audio output,
  regardless of any legacy `script`/`out` entries in the voice job.

Build the approved pilot, or substitute your episode slug:

```powershell
uv run python -m vap.episode build china-unity-pilot --stage all
```

The preview and render stages fail on a still camera; see "Motion is a build rule" in
[visual-grammar.md](docs/visual-grammar.md). Write storyboards by that document.

To stop earlier, or resume through a selected stage:

```powershell
uv run python -m vap.episode build china-unity-pilot --stage voice
uv run python -m vap.episode build china-unity-pilot --stage align
uv run python -m vap.episode build china-unity-pilot --stage preview
uv run python -m vap.episode build china-unity-pilot --stage render
```

The order is **voice → align → preview → render**. Each target includes its
predecessors, reusing valid cached results; `all` and `render` reach the same final
stage. Omitting `--stage` defaults to `all`. Voice includes existing trimming,
pauses, fades and loudness mastering. Alignment uses the existing GPU worker.
Preview resolves timing, validates components/camera coverage and renders the
first frame of every shot with its narration line. Render encodes H.264/AAC using
ANGLE and concurrency 1, then replaces the final MP4 only after success.

| Artifact | Location |
| --- | --- |
| Master voice and audit manifest | `episodes/<slug>/audio/voice.wav`, `voice.manifest.json` |
| Word timings and raw ASR evidence | `episodes/<slug>/audio/words.json`, `recognition-0.json` |
| First-frame preview sheet | `studio/out/<slug>-preview.png` |
| Individual shot first frames | `studio/out/<slug>-first-<shot-id>.png` |
| Resolved timing/assembly | `studio/out/<slug>-sync.json`, `<slug>-assembly.json` |
| Final video | `studio/out/episode-<slug>-synced.mp4` |
| Stage logs, cache and run summary | `studio/out/episodes/<slug>/` |

The builder creates a runtime storyboard in that last directory, binding the
current episode audio/words. It leaves your authored storyboard and historical
report references unchanged. On a complete cache hit, media files keep their
contents and modification times; logs append and `build-summary.json` records the
latest invocation. Cache keys include source/settings/code, tool versions, actual
audio/word data and local plate/font/B-roll bytes. Missing or changed outputs are
rebuilt even if their timestamps look current. Keep the ignored cache state to
retain stage-level reuse; deleting it causes stage execution again (the existing
raw TTS/ASR caches can still help).

Failures exit nonzero with the **stage name and log path**; dependent stages stop.
For example, `[align] FAILED ...; log: .../align.log` preserves the mismatch evidence
for review. Correct the affected narration/prosody/voice settings using
[voice.md](docs/voice.md), then rerun. The builder does not automatically rewrite
approved narration or force unresolved timestamps to pass validation.

A global lock at `studio/out/.episode-build.lock` prevents simultaneous CLI
builds, including different episodes. Heavy stages run sequentially and no Studio
server is started. After a killed process, check the PID in the lock and confirm
the build and its workers have stopped before manually removing that stale lock.
Use `npm run studio` from `studio/` yourself when you want the interactive editor.
