## Built

- `studio/src/episode/sync.ts`: original word-index, unique contiguous phrase and
  explicit-time anchor resolution. Phrase normalization handles case, punctuation,
  curly apostrophes and grouped numbers while retaining original word times.
  Missing/ambiguous phrases, invalid indices/times and invalid windows fail with
  paths into the storyboard instead of choosing an arbitrary match.
- Actual mono PCM16 samples are decoded by `wav.ts`. Pause detection uses 10 ms
  RMS windows at or below -45 dBFS and requires at least 3 eligible frames.
  Cuts choose the nearest admissible pause candidate within 18 rounded frames:
  midpoint for short pauses, nearest quiet frame for long pauses, earlier ties.
  Media endpoints are exempt. A missing nearby pause is an error. Quantization
  means the limit is on rounded frame indices, not an exact 0.6-second raw delta.
- `voiceSync` design tokens hold the policy: 3-frame label lead, 60-frame minimum
  shot, 3-frame minimum pause, 18-frame snapping window and audio thresholds.
  Explicit label anchors receive configurable lead, clipped to the scene window;
  their end remains fixed. The lead marks animation start, not full opacity.
- Validate positive ordered authored windows, snapped windows, minimum scene
  duration and contained component windows. Gaps of at least 60 frames become
  generated drift scenes. Shorter gaps extend an adjacent scene with a drift
  camera prefix/tail, preserving its active camera window and avoiding tiny shots.
  Generated IDs avoid collisions; outgoing transitions move to the gap end.
  Nominal windows cover every frame exactly once; intentional transition overlap
  continues to use the existing Episode renderer without moving the audio.
- Default metadata preparation runs this resolver after existing WAV hash and
  alignment checks. Explicit manual `timing` remains available for compatibility.
  Camera adapters support the active camera window and drift padding.
- `npm run sync:episode` writes resolved assembly, runtime storyboard and sync
  diagnostics. `--lead-frames=N` configures lead in sync/render helpers. Existing
  rendering now writes the resolved plan and a preview-input JSON, renders each
  exact scene-first composition frame, and calls `vap.qa.storyboard_preview`.
- The Python preview tool uses existing Pillow and token-supplied fonts, colors,
  sizes and spacing. It includes every shot and its complete narration line.
  A true first frame may still show outgoing content during a transition or an
  initially invisible overlay; it is not replaced with a later presentation frame.
- Added explicit phrase starts to three sandbox labels (Tibetan Plateau, Gobi
  Desert, 2,000 years). Together with two existing word/phrase anchors, all five
  labels now demonstrate the lead. Narration and shot anchors did not change.
- Updated `docs/storyboard.md` with policy, errors, compatibility and CLI usage.

## Decisions, deviations and open questions

The 2-second minimum is centralized in tokens. A short gap uses drift padding
inside a valid-length scene rather than producing a scene below that minimum.
This reconciles both acceptance requirements without silently discarding gaps.

No unresolved acceptance failures or user decisions remain for 4.3. Timing accuracy
still depends on the existing Whisper alignment; a 3-frame lead does not claim
phonetic accuracy beyond that input. The 60–90 s pilot and its required text
approval belong to step 4.4.
