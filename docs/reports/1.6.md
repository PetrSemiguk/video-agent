### Documented schema versus live verification

The official [OHM QLever documentation](https://wiki.openstreetmap.org/wiki/OpenHistoricalMap/QLever)
documents the daily global OHM index and these mappings:

| Concept | RDF representation |
|---|---|
| OHM identities / source_ref | `https://www.openhistoricalmap.org/node/<id>`, `/way/<id>`, `/relation/<id>` |
| Object type | `a <https://www.openstreetmap.org/relation>` or corresponding way/node type |
| Raw tags | `osmkey:` = `https://www.openstreetmap.org/wiki/Key:`; name, start_date, end_date, license, boundary, admin_level |
| Typed dates | `osm2rdfkey:` = `https://osm2rdf.cs.uni-freiburg.de/rdf/key#`; typed start_date/end_date |
| Political classification | Raw `boundary` / `admin_level` tag values; do not infer sovereignty just from a name |
| Geometry | `geo:hasGeometry/geo:asWKT`, with `geo:` = `http://www.opengis.net/ont/geosparql#` |

These are documentation findings, **not observed result rows from the live index**.
The prepared follow-up relation/way tags query is
`docs/requests/ohm-qlever-tags.rq` (LIMIT 10, no geometry); it has not been executed.
Raw `license` must remain in evidence; OHM default CC0 applies only when there is
no contrary explicit license. CC BY/CC BY-SA/other exceptions still require a
separate user decision and are excluded automatically.
