## Authorized alignment repair

Original mastering produced 67.97 s; a selective four-chunk repair produced
67.19 s. Both alignments failed, so work stopped and the user authorized a fix.
Diagnostics are retained, rather than treated as successful pilot inputs.

The root problems were one ASR numeric token owning multiple original words,
zero-duration Whisper words, short-year normalization, and `an` being heard as
`and`. Implemented these scoped fixes:

- Keep unprompted recognition unchanged. For ASR digit tokens/zero-duration words,
  expand **recognized text** into spoken forms and recompute acoustic DTW using
  the same installed model. No script text is fed into this pass.
- Join split grouped digits; support short three-digit years after `in`, excluding
  listed quantity suffixes. TTS normalization/cache semantics are unchanged.
  This contextual convention remains a heuristic for ambiguous number phrases.
- Timing-only 200 ms synthetic edge padding is removed from global offsets. Try
  median-filter widths 7, 3, 11, 1 in order, accepting only an identical recognized
  lexical sequence with positive monotone acoustic spans. Never split a span
  equally, add epsilon durations or force missing script words into the audio.
  Preserve raw ASR and refinement text/filter provenance in recognition JSON.
- Reject overlapping original word spans as unresolved, including number-token
  sharing. Version the recognition policy so stale ASR cache data is not reused.
- The prosody pause corrected `an`/`and` without changing narration words. Final
  DTW refinement was needed for chunks 2, 10, 12 (filter 7) and 14 (filter 3).
  The successful policy is `asr-normalized-dtw-v3`. Experimental runs remain only
  in ignored output; they are not silently substituted into final evidence.
- Updated `docs/voice.md` and added eight regression cases covering numbers,
  short years/quantities, overlap rejection, valid acoustic paths and refusal to
  fabricate times when every path is invalid.
