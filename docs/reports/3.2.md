TTS generation, CPU watermark detection and waveform rendering ran sequentially.

## Built

- `postprocess.py`: edge trim using 10 ms RMS frames at -50 dBFS with 20 ms safety
  handles; reject an all-silent chunk, preserve all interior silence. Apply existing
  5 ms linear fades after trimming. Record source/removed/retained samples.
- `chunk.py` / `tts.py`: sentence 250 ms, paragraph 600 ms and section 1 s inserted
  gaps. Markdown headings become unspoken section boundaries. Budget-split
  continuations do not acquire sentence gaps. `[pause 1.0]` overrides the automatic
  gap at that boundary; support leading/trailing explicit pauses and zero.
  Consecutive directives add; each accepts 0–30 seconds. Malformed directives
  fail before synthesis and never reach TTS.
- `lexicon.yaml`: JSON-compatible YAML flat dictionary, using the standard parser
  without new dependencies. Qing -> Ching, Xi'an -> Shee ahn, Chongqing -> Chong
  ching, Wrocław -> Vrots wahf. Match complete names case-insensitively, normalize
  curly apostrophes, keep original script in manifests. These are editable English
  respelling hints, not IPA/native-pronunciation guarantees.
- Normalizer version 3 invalidates old normalized cache keys. Raw float TTS chunks
  remain untouched; post-processing and pause changes require only reconstruction.
- `tts.py` now writes schema-2 manifests, a float `voice.pre-loudnorm.wav` audit
  input and normalized PCM16 `voice.wav`. Manifest retains precise sample/second
  spans plus all trim settings, section/explicit pauses, loudnorm passes and checks.
- System ffmpeg two-pass loudnorm: -16 LUFS, LRA 11, internal TP target -1.6 dBTP
  to leave 0.1 dB delivery margin. Request linear mode; both real examples require
  dynamic fallback to satisfy the peak limit. Output explicitly mono 24 kHz PCM16.
  Remeasure encoded WAV: require -16 +/-0.2 LUFS and TP <= -1.5 dBTP, unchanged
  sample count and finite mono audio. Replace destination only after checks pass.
- De-click QA checks chunk starts/ends and file edges before and after loudnorm.
  A sample step >0.001 (-60 dBFS) fails. This measures splice discontinuities; it
  cannot establish that no click exists inside generated speech.
- Updated voice docs and comparison resume compatibility for schema 2. Historical
  3.1 WAVs and committed measurements were not overwritten. The comparison command
  will regenerate according to current processing when invoked again.
