# Step 4.1 — Storyboard schema

Status: **complete**. Strict Zod authoring schema, exported JSON Schema, CLI,
sandbox example and authoring documentation implemented. Step 4.2 Episode
assembly and step 4.3 anchor/timeline resolution have not started.

## Protocol and research

Read AGENTS.md, roadmap section 0 / step 4.1, report 3.3, the production component
registry/props schemas, camera presets, transition schema and existing TypeScript
documentation scripts. Initial git status was clean except the existing ignored
pytest-cache permission warning. Research preceded implementation.

Checked installed **Zod 4.5.4** and its local to-json-schema declarations against
the [official Zod JSON Schema documentation](https://zod.dev/json-schema).
Use input mode so defaulted component props remain optional authoring inputs.
Custom validators/refinements cannot all be represented in standard JSON Schema;
do not silently export custom map payloads as unconstrained objects.

No dependencies, package versions, model/media sources or licenses changed. npm/
npx only; Python execution only via uv. No GPU models, heavy concurrent jobs or
background Studio server. Existing licensed Barlow Condensed and design tokens
were reused for the contract review still.

## Built and decisions

- `studio/src/storyboard/schema.ts`: schemaVersion 1; English episode metadata at
  token fps 30; declared plate aliases/local names; repository-relative audio and
  word references; nonempty shots with ids, plate, start/end anchors, camera,
  layers and optional outgoing transition.
- Anchors are strict mutually exclusive `{word}`, `{phrase}` or `{time}` objects.
  Original word indices are zero-based. Start words/phrases refer to the first
  onset; end words/phrases to the last word's end. Same-word windows are valid.
  Same-kind reversed ranges fail. Mixed anchors remain unresolved data.
- All six existing camera presets have serializable strict params: establish,
  drift, hold, focusOn, flyTo, followLine. Coordinates, zoom/angle bounds,
  bbox ordering and measured-line fractions are checked. Frame counts for shots
  are not duplicated in camera descriptors; they come from later resolution.
- Layers use a discriminated union covering **all 16 production registry types**.
  Each branch reuses the **actual component props schema instance**, including
  semantic refinements. Type inference preserves the type/props relationship.
  Infrastructure and diagnostics are not valid layer types. Optional layer
  windows inherit the corresponding shot endpoint.
- Unique plate/shot ids, layer ids per shot, declared plate references, same-kind
  endpoint ordering and absence of a final outgoing transition are checked.
  Local paths reject traversal, backslashes, absolute paths and URLs. Animated
  transitions reuse the production schema/defaults; explicit cut is supported.
- `jsonSchema.ts` exports Draft 2020-12 to `docs/storyboard.schema.json` (136461
  bytes). Existing map custom validators now export named **structural** contracts
  for Polygon/MultiPolygon and measured LineString payloads; renderer/runtime
  validators retain their previous behavior/types. Unexpected unrepresentable
  schemas throw. No global unrepresentable-any fallback.
- Standard JSON Schema lacks some cross-field/refinement checks. Export lists
  them under `x-runtime-validation`; **the Zod CLI is authoritative**. This is an
  explicit portability limit, not a claim of complete Python/Zod equivalence.
  Python can consume the generated contract with a Draft 2020-12 validator; a
  Python validation dependency was not needed because the roadmap permits npm CLI.
- `studio/scripts/storyboard.cjs`: installed TypeScript compiler loads TS/TSX
  schemas, matching the existing catalog-generation approach, without a new runner.
  Added `schema:storyboard` and `validate:storyboard` npm scripts. JSON report and
  exit codes: valid 0, invalid input/assets 1, usage 2. Full error paths preserve
  props refinements. Optional `--check-files` verifies referenced files, plate
  metadata, complete alignment and exact audio SHA-256 agreement.
- `episodes/_sandbox/tts-test/storyboard.json`: six shots following all six
  narration sentences, three anchor forms, five camera presets, optional layer
  windows, production text/card props and outgoing transitions. References the
  measured step 3.2 WAV and committed step 3.3 alignment, not an unrelated voice.
- `docs/storyboard.md`: input for a future storyboard agent, field/anchor/camera/
  layer/transition contracts, CLI, portability limits and deferred runtime checks.

No new asset/GeoJSON downloads were made. The example uses labels/text over the
declared existing plate; it is not a publication-ready sourced episode. Actual
camera coverage, layer fit, phrase ambiguity/index availability, transition
overlap, gap filling and frame rounding require later resolution/rendering. No
anchor resolver, assembler, Episode composition or episode MP4 was introduced.
Component duration defaults are not shot timing: future assembly must pass
resolved layer durations to components rather than override anchors with defaults.

## Open questions / limits

No user decisions are required for 4.1. Portable JSON Schema intentionally does
not replace Zod semantic validation. Reference existence/hash checks are optional
so scripts can be authored before local media is generated. The example's WAV
is ignored and must be regenerated using the documented voice command on a new
checkout. Rendering/sync acceptance belongs to 4.2–4.3.

Suggested commit: `feat(storyboard): add schema, validator and sandbox example`.
